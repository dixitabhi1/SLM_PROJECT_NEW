5. Factual Findings Derived Directly from Reserve Data

  • Reserve Evaluation Finding: The frozen Specialist SLM Pipeline (v1.3, 3.82B parameters, zero external LLM calls) achieves 87.0% accuracy (87/100) on the quarantined reserve evaluation set, outperforming GPT-OSS-120B B1 (80.0%) by +7.0 percentage points and qwen/qwen3.8-27b B1 (82.0%) by +5.0 percentage points.
  • Multi-Slot Execution Stability & Concurrency: Across independent evaluations under 3-slot concurrency (-np 3), Specialist Pipeline Run 1 (87.0%) and Run 2 (87.0%) achieve 100.0% verdict concordance (100/100 items), with a paired difference of +0.0 pp [95% CI: +0.0, +0.0].
  • Head-to-Head Outcomes (“SLM Not Beaten”): In pairwise symmetric comparisons, the 3.82B SLM pipeline was not beaten on 89.0% of items vs 120B B1 (18 wins, 69 ties, 2 both wrong, 11 losses) and 89.0% of items vs 27B B1 (16 wins, 71 ties, 2 both wrong, 11 losses).
  • Tool-Required Performance: On Compound Tool-Required tasks ($N=20$), the small system achieves 95.0% (19/20), surpassing both tool-equipped LLM baselines (120B B1 at 20.0%, 27B B1 at 35.0%).
  • Non-Tool-Required Performance (80 Items): On the 80 reserve items without compound tool-required tasks (60 atomic + 20 compound solvable), the SLM scored 68/80 (85.0%), underperforming GPT-OSS-120B (76/80, 95.0%) and Qwen-3.8-27B (75/80, 93.8%). The SLM's overall accuracy lead stems from the compound tool-required category.
  • Parameter Efficiency & Size Ratios: The pipeline operates with 7.1× fewer parameters than qwen/qwen3.8-27b and 31.4× fewer parameters than GPT-OSS-120B, with zero cloud spend ($0.00 cloud API cost on pipeline path).

6. Methodological Caveats & Threats to Validity

  • Cryptographically Quarantined Reserve Split: Evaluated strictly on the quarantined 100-item reserve partition locked by pre-registered SHA-256 digest before pipeline execution. The reserve was not regenerated: the same split (bacd6c5ea2443cb0...) was used; 89 items were previously run by v1.1 during an aborted trial with answers uninspected. All outputs and logs are append-only.
  • Baseline Fairness and Execution: Under baseline condition B1+code, LLMs were granted sandbox execution for Python code emitted on compound tasks, eliminating asymmetric advantages. Real finish_reason is captured for every call.
  • Floating-Point Non-Determinism Across Concurrency Slots: In local GPU execution (Vulkan0 with --np 3 parallel slots), non-atomic reduction operations in llama.cpp introduce minor sampling variance across repeated runs even at temperature = 0.0 (100.0% concordance across 100 items).
  • Strict Truncation Fail-Loud Policy: Per Hard Rule 3, any completion truncated by token limits (finish_reason == "length") is scored strictly as 0.
